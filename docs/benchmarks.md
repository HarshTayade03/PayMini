## 2. Password Hashing Benchmark (Argon2id vs Plain Digests)

Argon2id is intentionally configured to balance security (resisting GPU brute force) and server throughput.

### Measured Execution Latency (100 iterations on `python:3.12-slim`):
- **Argon2id `hash()`:** ~45 ms per operation
- **Argon2id `verify()`:** ~42 ms per operation
- **SHA-256 (for comparison):** ~0.003 ms per operation

*Takeaway:* Argon2id is approximately **14,000 times slower** than SHA-256 by deliberate design. This renders offline dictionary attacks prohibitively expensive while remaining imperceptible to a human user logging in.

## 3. Database Index Query Efficiency (EXPLAIN Plan)

We evaluated query performance for cursor-paginated transaction history queries on the `ledger_entries` table:

```sql
EXPLAIN ANALYZE
SELECT id, entry_type, amount_paise, balance_after_paise, description, created_at
FROM ledger_entries
WHERE wallet_id = '9b1deb4d-3b7d-4bad-9bdd-2b0d7b3dcb6d'
ORDER BY created_at DESC
LIMIT 20;
```

### Measured Execution Plan:
- **Without Composite Index (`ix_ledger_entries_wallet_created`):**
  - Plan: `Seq Scan on ledger_entries` followed by `Sort (quicksort)`.
  - Cost: Scales linearly with total rows in table ($O(N)$).
- **With Composite Index `(wallet_id, created_at DESC)`:**
  - Plan: `Index Scan using ix_ledger_entries_wallet_created on ledger_entries`.
  - Cost: Index scan cost $O(\log N)$, eliminating memory sorting overhead.
